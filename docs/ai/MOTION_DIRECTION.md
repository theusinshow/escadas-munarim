# Motion Direction

> Generated by Coded by M — Site Architecture System. Source of truth: `/docs/ai/DISCOVERY.md` and `/docs/ai/DECISIONS_LOG.md`.

## Core Motion Concept

**O movimento do site é a geometria da escada.**

Nada anima "para ficar bonito". Existe **um** sistema de motion, e todo parâmetro dele — offset,
delay, duração, direção — é derivado da própria escada: a proporção do degrau, o traço do desenho
técnico, o giro do caracol. É por isso que ele não pode ser transplantado para outro site: o site do
concorrente teria que fabricar as mesmas escadas.

O pedido do desenvolvedor foi literal: *"texto subindo degrau ou descendo em espiral, algo bem
técnico, bonito, direto e sem IA flops."* A tradução técnica está abaixo.

**A constante do sistema:**

```
espelho (riser) = 18   ·   piso (tread) = 28
```

Essa razão governa offsets e tempos em todo o site. É a proporção de conforto de subida de uma escada
residencial — o número existe fora do site.

## Motion Language

### 1. Traço técnico — `draw`

O desenho SVG se constrói conforme o scroll, como se estivesse sendo desenhado na prancheta.

- Técnica: `stroke-dasharray` / `stroke-dashoffset` com `ScrollTrigger` em modo `scrub`.
- Ordem de desenho: **estrutura → degraus → cotas**. Nunca aleatória. É a ordem em que um projetista
  desenha, e ela carrega a mensagem de "isto é um projeto".
- Easing: **linear**. Desenho mecânico não acelera.
- Peso de traço: 1,5px `--primary` na estrutura, 1px `--inox` no corrimão, 1px `--accent` na cota ativa.
- Duração: nenhuma própria — atrelado ao progresso do scroll da seção.

### 2. Degrau — `stepIn`

A entrada padrão de qualquer grupo de elementos. Substitui integralmente o fade-up genérico.

```js
// razão real do degrau — não mexer sem mexer na escada
const RISER = 18, TREAD = 28;
const SCALE = 1.6;                 // desktop; 1.0 em <768px

// elemento i entra deslocado em degrau e assenta em (0,0)
from: { x: -TREAD * SCALE * 0.25, y:  RISER * SCALE * 0.25, opacity: 0 }
to:   { x: 0, y: 0, opacity: 1 }

duration: 0.28   // 28 = piso
stagger:  0.18   // 18 = espelho
ease: 'cubic-bezier(0.22, 1, 0.36, 1)'
```

- **Subindo** (`x` negativo → 0, `y` positivo → 0): padrão. O bloco monta da esquerda-baixo para a
  direita-cima, como quem sobe.
- **Descendo:** só quando a seção fala de descida ou de lance descendente. Inverte o sinal.
- O stagger codifica geometria real — é por isso que ele não é U17 (motion decorativo).

### 3. Espiral — `spiral`

**Exclusivo de `/escadas/caracol`.** Usado uma vez, onde é literalmente verdade.

- Os elementos entram ao longo de um arco em torno do eixo central do desenho: `rotate` de `-14deg`
  para `0`, combinado a um deslocamento em arco de raio `R = 120px` (desktop) / `64px` (mobile).
- O desenho da escada caracol gira até `360°` sobre o progresso de scroll da seção, revelando um
  degrau por vez — cada degrau entra com o mesmo `stagger: 0.18`.
- Nunca aplicar `spiral` fora dessa rota. Um efeito que aparece em todo lugar deixa de significar algo.

### 4. Cota — `dimension`

A linha de cota se estende das pontas para o centro (200ms, ease-out), e o valor em DM Mono aparece
**sem animação** — número não anima. Nada de contador crescente.

## Hierarchy

1. **Primary narrative motion** — `draw` nos desenhos técnicos das páginas de tipo, do hero e do
   `/como-funciona`. É o argumento de produto.
2. **Section transitions** — `stepIn` na entrada de blocos de conteúdo.
3. **Microinteractions** — hover de card e botão, foco, abertura de FAQ, chips de filtro.
4. **Decorative motion** — **não existe neste projeto.** Não há parallax, não há partícula, não há
   fundo animado, não há cursor customizado.

## Microinteractions

- **Card de tipo:** hover eleva o traço do desenho de 1px para 1,5px e troca a cor para `--accent`.
  Sem translate, sem sombra, sem zoom de imagem. 160ms.
- **Botão:** hover troca para `--accent-hover` em 160ms. Sem crescimento, sem brilho.
- **Link:** sublinhado de 1px engrossa para 2px em 120ms.
- **Foco:** ring de 2px `--ring` com offset 2px, **sem transição** — foco precisa ser instantâneo.
- **FAQ:** `<details>` nativo, abertura de 200ms com altura animada.
- **Chip de filtro (`/obras`):** troca de estado em 120ms; o grid re-arranja com FLIP de 240ms.
- **Botão flutuante de WhatsApp:** aparece por opacidade após 200px de scroll. **Não pulsa, não
  balança, não abre balão automático.**

## Mobile Behavior

- `SCALE` do `stepIn` cai de 1.6 para 1.0 — o mesmo degrau, menor.
- `draw` em scrub é mantido, mas com `ScrollTrigger.normalizeScroll` desligado e o desenho simplificado
  (menos paths) abaixo de 768px.
- `spiral` reduz o raio para 64px e o giro de 360° para 180°.
- Stagger máximo de 6 elementos por grupo — em lista longa, os demais entram juntos. Stagger longo em
  mobile vira espera.
- Nenhuma animação disparada por scroll horizontal.

## Accessibility

- Respect `prefers-reduced-motion`.
- **Fallback completo, não degradado:** com `reduce`, todo desenho SVG aparece 100% traçado, todo
  `stepIn` vira estado final estático, o `spiral` não gira. Nenhum conteúdo fica escondido.
- Implementação: `gsap.matchMedia()` com `(prefers-reduced-motion: reduce)` definindo o estado final
  direto, nunca `duration: 0` sobre um estado inicial invisível.
- **Nenhum conteúdo depende de animação para ser lido.** Com JS desabilitado, todas as rotas são
  legíveis e navegáveis — os SVGs renderizam completos por padrão no HTML, e o JS só aplica o estado
  inicial da animação quando vai animar.
- **E nada que já foi lido some para reaparecer** (`DEC-018`). Se o JS assumir depois da janela de
  800ms e o elemento já estiver na tela, a entrada dele é cancelada — ele fica quieto onde está.
  Medido: em 3G o HTML pinta aos 468ms e o JS só chega 1,17s depois; sem essa regra, o desenho sumia
  na frente de quem já estava lendo.
- Nada pisca acima de 3 vezes por segundo.

## Performance Restrictions
- Do not compromise LCP, CLS or INP.
- Avoid heavy animation libraries without need.
- Avoid WebGL unless justified.

**Específico deste projeto:**
- GSAP + ScrollTrigger apenas, importados por módulo e só nas rotas que animam. **Sem Lenis, sem
  smooth-scroll** — scroll sequestrado atrapalha quem está lendo especificação técnica.
- Anima **só** `transform` e `opacity`, mais `stroke-dashoffset` nos SVGs. Nunca `width`, `height`,
  `top` ou `left`.
- Estado inicial da animação aplicado por JS, nunca por CSS — assim o HTML estático já é o estado
  final e não há flash de conteúdo invisível se o JS falhar.
- Todo elemento animado tem espaço reservado no layout. **CLS de motion é zero.**
- O hero não anima antes do LCP: o `draw` do traço só inicia após a imagem principal carregar.
- WebGL: **não**, sem exceção nesta fase.


## Curva compartilhada

`cubic-bezier(0.22, 1, 0.36, 1)` existe em dois lugares: o `CustomEase` que o GSAP registra como
`"degrau"` e o token `--ease-degrau` do `@theme`, que gera o utilitário `ease-degrau`. **É a mesma
declaração**, para que a transição feita em CSS e a feita em JS não possam divergir com o tempo.
